# Event Sourcing & FlowEvents

MessageWeave is **event-sourced**: every action — a message, an edit, a membership
change, a topic change — is recorded as an immutable `FlowEvent`. Current room
state can be derived by replaying events, and MessageWeave also maintains a small
room-state projection so common state reads do not need to replay the whole
timeline.

## The FlowEvent

A `FlowEvent` is the atomic, immutable unit of state. Once written, it is never
updated or deleted. Each event carries:

- **`id`** — a unique identifier generated by the storage backend.
- **`roomId`** — the conversation boundary the event belongs to.
- **`senderId`** — the entity that initiated the event.
- **`type`** — a dot-notated namespace, e.g. `message.text` or
  `room.state.name`.
- **`content`** — a JSON-serializable payload, schema-less by design.
- **`sequenceId`** — a globally monotonic cursor assigned at publish time (see
  [Sync](./sync.md)).

## Why immutability

Because events are never mutated, MessageWeave gets several properties for free:


- **Auditability** — the full history of a room is always recoverable.
- **Time travel** — you can reconstruct a room's state as of any `sequenceId`.
- **Conflict-free replication** — appending is the only write operation.

## Publishing events

Append an event with `publishEvent`. It returns the stored event together with
the `sequenceId` assigned to it:

```ts
const { event, sequenceId } = await flow.publishEvent({
  roomId: room.id,
  senderId: "u1",
  type: "message.text",
  content: { body: "hello" },
});
```

## Messages, edits & deletes

For typical chat messaging, MessageWeave provides convenient first-class methods
that handle proper event typing, validation, and parent DAG linkage:

```ts
// 1. Send a plain text message (or reply)
const msg = await flow.sendMessage({
  roomId: room.id,
  senderId: "u1",
  body: "Hello world!",
  replyToMessageId: parentMessageId, // optional thread parent
});

// 2. Edit an existing message (creates an immutable `message.edit` event)
await flow.editMessage({
  roomId: room.id,
  senderId: "u1",
  messageId: msg.event.id,
  body: "Hello world (edited)!",
});

// 3. Delete a message (creates an immutable `message.delete` tombstone)
await flow.deleteMessage({
  roomId: room.id,
  senderId: "u1",
  messageId: msg.event.id,
  reason: "Mistake",
});
```

## Projecting the timeline for UI

Because messages are event-sourced, edits and tombstones do not overwrite previous
records. To present a unified list of messages in your UI, use `projectTimeline`:

```ts
import { projectTimeline } from "messageweave";

const events = await flow.getRoomTimeline(room.id);
const messages = projectTimeline(events);

// Returns UI-ready ProjectedMessage objects:
// [{ id, roomId, senderId, body, isEdited, isDeleted, createdAt, ... }]
```
